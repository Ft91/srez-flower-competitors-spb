# Настольное приложение «Срез»

Версия 0.7 для Windows x64. PyQt6 создаёт отдельное окно, а Qt WebEngine показывает внутри него интерфейс из этапа 6. FastAPI запускается вместе с окном и останавливается при его закрытии. Функции сайта и настольного приложения используют один и тот же код.

## На этом компьютере

Откройте PowerShell в папке проекта и выполните:

```powershell
.\start-desktop.ps1
```

Обновлённый Start-Srez.cmd сразу закрывает служебную консоль после запуска приложения. Скрипт start-desktop.ps1 найдёт `..\Srez-Windows\Srez.exe` и передаст ему папку текущего проекта. Поэтому будут доступны уже введённый ключ, сохранённые снимки и анализы. Запуск прежнего сервера через start.ps1 не требуется.

Сервер выбирает свободный порт и слушает только 127.0.0.1. Он не конфликтует с веб-версией на портах 8000/8001. Для одной папки данных разрешено одно настольное окно.

## Отдельный .exe

Откройте `Srez.exe` в папке, куда у вас есть право записи. Устанавливать Python или PyQt6 не нужно. При первом запуске рядом появится `Srez-data`:

- `.env` — настройки провайдера и ключ;
- `runtime/history/history.sqlite3` — история;
- `runtime/history/artifacts` — исходные материалы;
- `runtime/selenium-cache` — служебные файлы Selenium.

Кнопка «Папка данных» открывает эту папку. При замене .exe сохраните Srez-data. Переносить историю нужно вместе с каталогом artifacts; переносить весь Srez-data проще. Для резервной копии сначала закройте приложение.

Для своей существующей папки:

```powershell
.\Srez.exe --data-dir "C:\путь\к\проекту"
```

Демонстрационный пример встроен в приложение и доступен без ключа. Новая копия .exe не содержит ваши ключи и личную историю.

## Настройки и работа

«Настройки ИИ» открывает форму выбора провайдера, ключей и моделей. Ключи скрыты в полях. После сохранения встроенный сервер перезапускается и применяет изменения. Это не отправляет запрос к модели.

Наличие ключа не проверяет его действительность. Переменные окружения Windows имеют приоритет над .env, как и в веб-версии.

Для нового анализа нужен интернет и ключ выбранного провайдера. Для сбора сайтов нужен установленный Google Chrome; Selenium подбирает драйвер при первом сборе. Встроенный Qt WebEngine служит интерфейсом и не заменяет Chrome для Selenium.

Обзор, формы сайта/текста/изображения, сравнение, история и демонстрационный пример работают через тот же интерфейс. JSON сохраняется через системный диалог. Ссылки на поставщиков открываются в обычном браузере. Пока идёт сбор или анализ, приложение просит дождаться завершения перед закрытием или изменением настроек.

Первый запуск одного .exe может занять некоторое время: PyInstaller распаковывает встроенные библиотеки во временную папку. Постоянные данные в этой временной папке не хранятся.

## Если встроенное окно не отображается

В панели приложения есть «Открыть в браузере». Кнопка открывает тот же локальный интерфейс; окно «Срез» должно оставаться открытым, поскольку оно управляет сервером.

В среде исполнения Codex при проверке исходников процесс отображения Qt завершился с кодом 49. Поэтому факт сборки и проверки API не означает успешную визуальную проверку окна. Позже пользователь подтвердил запуск приложения: пустым оказалось служебное окно cmd.exe. Полный статус — в [результате этапа 7](../STAGE7-RESULT.md).

## Сборка из исходников

Windows x64, Python 3.12:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip --isolated install --index-url https://pypi.org/simple -r desktop/requirements.txt
.\.venv\Scripts\python.exe build.py
```

Результат: `dist/Srez.exe`. Для другой папки укажите `--dist-dir`. Сборщик включает только явно перечисленные ресурсы: интерфейс, три сохранённых ответа и пустой шаблон настроек. .env, runtime, тестовые ключи и текущая история не включаются.

Сборка выполняется с отдельным PATH: Python и системные папки Windows. Это исключает случайное включение одноимённых DLL из сторонних инструментов. Например, библиотека ICU из Poppler оказалась несовместима с Qt; путь к ней больше не участвует в сборке.

## Проверки

Для полного набора тестов установите desktop/requirements.txt. При установке только requirements.txt проверка Qt пропускается; остальные проверки веб-приложения выполняются.

```powershell
.\dist\Srez.exe --self-test ".\runtime\stage7\offline.json"
.\dist\Srez.exe --data-dir "." --ui-smoke ".\runtime\stage7\ui.json"
```

Первая команда проверяет библиотеки, локальные маршруты, сохранённые ответы, наличие Selenium Manager и сохранение истории/файлов после перезапуска. Используется отдельная временная папка, удаляемая после проверки. Вторая открывает настоящее окно, проверяет появление пяти карточек и сохраняет PNG только при успехе; затем закрывает окно. Эти команды не запускают сбор поставщиков и не обращаются к ИИ.
