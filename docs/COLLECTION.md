# Сбор страниц и история — этап 5

## Как запустить

Нужны Google Chrome и окружение из README. Запустите start.ps1 из обычного PowerShell Windows. При первом сборе Selenium Manager подберёт и загрузит ChromeDriver в runtime/selenium-cache; нужен интернет. Личный профиль Chrome не используется: на каждый сбор создаётся отдельный временный профиль, после работы браузер закрывается.

Список пяти конкурентов и URL находится в backend/config.py, переменная COMPETITORS. Доступные записи возвращает GET /competitors.

Откройте http://127.0.0.1:8000/docs. У нужного метода нажмите Try it out, вставьте тело запроса и нажмите Execute.

Только сохранить все пять главных страниц, без запросов к модели:

```http
POST /collect
```

```json
{}
```

Собрать одного поставщика:

```json
{"competitor_ids": ["floradomspb"]}
```

Пример работы — сбор главной страницы ФлораДомСПБ, затем анализ текста и первого экрана:

```http
POST /parsedemo
```

```json
{"competitor_ids": ["floradomspb"], "modes": ["text", "image"]}
```

**Этот вариант отправляет два запроса выбранному сервису ИИ и расходует его баланс.** Ключ берётся из локального .env. Для всех пяти поставщиков передайте список их ID; это до десяти запросов к модели. Повторный запуск создаёт новые снимки и новые анализы, автоматических повторов платных запросов нет.

Можно выполнить демонстрацию из второго окна PowerShell:

```powershell
..\..\work\flower-competitor-env\Scripts\python.exe scripts/collect_demo.py
```

Только сбор пяти страниц:

```powershell
..\..\work\flower-competitor-env\Scripts\python.exe scripts/collect_demo.py --collect-only --competitors 7flowers optflor floradomspb florografia tsvetomania
```

На другом компьютере используйте .venv\Scripts\python.exe.

## Где лежат результаты

- runtime/history/history.sqlite3 — постоянная история.
- runtime/history/artifacts/<ID>/ — файлы конкретной записи.
- У снимка: page.txt, page.json, viewport.png и full-page.png.
- У анализа: input.txt либо очищенное от метаданных изображение input.png/input.jpg. JSON результата хранится в истории.
- runtime/demo-reports — отчёты запусков через collect_demo.py.

Результат /collect содержит ID снимка, статус, дату, источник и ссылки на файлы. GET /history показывает записи от новых к старым. GET /history/<ID> возвращает полный результат. GET /history/<ID>/files/<имя> выдаёт файл из этой записи.

История поддерживает limit (1–100), offset, competitor_id и kind (capture/text/image). Например: /history?competitor_id=floradomspb&kind=text&limit=20.

Ручные /analyze_text и /analyze_image тоже сохраняются в историю; ID добавляется в поле history_id. Анализ снимка связан с ним через parent_id. Отраслевой формат analysis остаётся версии 0.4; у приложения версия 0.5.0.

Чтобы повторно проанализировать уже сохранённый снимок без загрузки сайта:

```http
POST /captures/<ID>/analyze
```

```json
{"modes": ["text"]}
```

Это новый платный анализ старого материала: дата сбора страницы сохраняется.

## Что именно собирается

Для каждого ID открывается одна главная страница. Chromium прокручивает её ограниченное число раз для загрузки отложенных блоков и возвращается наверх. Сохраняются видимый текст DOM и два изображения: первый экран 1440×900 и страница высотой до 12 000 пикселей. Если страница длиннее, ограничение отмечается в warnings. Снимок не подтверждает, что все сетевые ресурсы загрузились.

На ИИ передаются до 40 000 символов текста и отдельно первый экран. Полный текст остаётся в исходном снимке; ограничение входа явно отражается в input_notes. По одному экрану нельзя судить о блоках ниже. Контрольные суммы SHA-256 в artifacts позволяют проверить, какие файлы сохранены.

Кнопки, формы, выбор города и согласие на cookies не нажимаются. Каталог, PDF и Excel по ссылкам не скачиваются. Прайсы этапа 2 остаются отдельными материалами. CAPTCHA не обходится. Несколько типичных признаков страницы защиты останавливают анализ; это эвристика, а не гарантия распознавания любой защиты.

Сайт может показать другой регион или перекрыть предложение баннером. Данные нужно сверять по сохранённому скриншоту. Дата сбора не означает дату актуальности цены.

## Ошибки и повторные запуски

Снимки и анализы имеют собственные записи. Ошибка одного поставщика не стирает успешные результаты других. В ответах пакетных методов проверяйте поле success и статус каждого элемента: HTTP 200 означает, что пакетный запрос обработан, а не что все сайты и модели отработали успешно.

При перезапуске сервера история остаётся в SQLite. Одновременно запись выдерживает несколько запросов; Chromium ограничен одним сбором на процесс. Используйте один сервер, как в start.ps1. Если процесс принудительно завершён посреди операции, запись может остаться running — это незавершённая попытка, не успешный результат. Можно повторить запуск; старые материалы останутся.

История не удаляется автоматически. Для резервной копии остановите сервер и скопируйте всю папку runtime/history. Исходники и архивы проекта её не включают.

## Если Chrome не запускается

- Проверьте запуск Chrome на этом компьютере и доступ к выбранному сайту.
- Для нестандартного пути укажите CHROME_BINARY в .env. Для заранее скачанного совместимого драйвера — CHROME_DRIVER. После изменения перезапустите сервер.
- При сбое загрузки драйвера проверьте интернет и свободное место.
- При page_timeout можно повторить сбор позднее; PAGE_TIMEOUT_SECONDS задаёт предел загрузки, от 5 до 90 секунд.
- В текущей среде исполнения Codex Chrome завершался из-за ошибки доступа в графическом процессе. Для проверки нужно запускать start.ps1 из обычного PowerShell Windows. После запуска сервера из обычного PowerShell сбор страниц был успешно подтверждён.
