# Формат анализа 0.4

Ниша: оптовые срезанные цветы. Регион интереса: Санкт-Петербург. Один запрос анализирует один переданный материал, а не весь сайт и не весь рынок.

## Текст: POST /analyze_text

Вход: text (10–40 000 символов), source_name, необязательные source_url и captured_at (дата получения материала с часовым поясом).

Ответ содержит schema_version=0.4, source, analysis, evidence_check и price_checks. Адрес и дата источника копируются из запроса, а не генерируются моделью. Приложение не посещает переданный URL.

### Условия закупки: analysis.facts

| Поле | Что извлекаем |
|---|---|
| assortment | Виды цветов и ассортимент |
| origin_countries | Прямо названные страны происхождения |
| farm_names | Конкретные названия ферм, если они есть |
| minimum_order | Минимальная сумма или партия с единицей |
| packaging_and_mixes | Пачки, коробки, стебли, смешивание сортов |
| availability_and_preorder | Наличие, предзаказ, сроки, регулярные поставки |
| delivery | Условия доставки с акцентом на СПб |
| payment | Предоплата, способы оплаты, отсрочка |
| claims | Условия претензий по качеству и количеству, брак, компенсации |
| ordering | Указанные способы оформления заказа |
| quality_promises | Заявления поставщика о качестве и стабильности |

Каждое поле содержит status, value и evidence_quotes.

| Статус | Значение |
|---|---|
| stated_by_supplier | Условие или обещание есть в материале. Это не независимое подтверждение его исполнения |
| not_stated | Не указано в изученном материале; value=null, evidence_quotes=[] |
| conflicting | В материале противоречащие условия; приведены минимум два разных фрагмента |

Фразы «200 плантаций» недостаточно для списка названий ферм. Вопрос «Есть ли отсрочка?» без ответа не подтверждает отсрочку. Отсутствие сведений об услуге не означает, что услуги нет.

### Как формируются цитаты

Сервер разбивает исходный текст на короткие фрагменты и присваивает им ID. Модель выбирает ID, а сервер копирует соответствующие цитаты из исходного материала. Ссылка на несуществующий ID отклоняется с evidence_mismatch. Дополнительно проверяется присутствие цитат в тексте с нормализацией пробелов.

Эта проверка подтверждает происхождение цитаты. Она не доказывает истинность рекламного заявления и не гарантирует, что модель верно истолковала фрагмент. Связь между выводом и цитатой всё равно нужно проверять.

### Примеры цен: analysis.price_examples

До 6 примеров; это не полный прайс, не поиск самого дешёвого предложения и не подтверждение актуальности.

Для каждого примера: flower, variety, stem_length_cm, stems_per_box, amount, currency, unit, price_kind, valid_date_label, conditions, evidence_quotes.

- unit: stem, bunch, box или null, если единица не указана.
- price_kind: exact либо from; «от 90» сохраняется как нижняя граница.
- Неуказанные сорт, длина, упаковка, валюта и дата остаются null.
- Дата сохранения страницы и год копирайта не становятся датой цены.
- Пересчёта валют, средней цены и общей стоимости в этом этапе нет.

price_checks создаётся сервером: перечисляет отсутствующие параметры и напоминает о правилах сопоставления. Даже полностью заполненная позиция не объявляется автоматически сопоставимой с другой.

### Выводы

summary собирается приложением из основных извлечённых полей с атрибуцией источнику. claimed_advantages — заявленные преимущества, purchase_constraints — прямо указанные ограничения, оба массива с цитатами. questions_to_supplier приложение формирует по незаполненным или противоречивым полям и неполным ценовым данным. limitations задаётся приложением: модель не сочиняет отдельную сводку, вопросы и оговорки.

## Скриншот: POST /analyze_image

Multipart: file (PNG/JPEG/WEBP, до 8 МБ и 25 млн пикселей); необязательные source_name, source_url, captured_at.

Ответ: описание, читаемые visible_business_terms, общая субъективная оценка design_score 0–10 с объяснением и пять отдельных критериев:

- readability — читаемость;
- b2b_offer_clarity — ясность предложения для оптового покупателя;
- navigation_clarity — видимая навигация;
- contact_visibility — заметность контактов;
- ordering_path_clarity — насколько по экрану понятен путь к заказу.

У критериев score может быть null, если оценить нельзя. Неизвестное не заменяется нулём. Итоговая оценка не является математическим средним или объективным рейтингом бизнеса.

Цитаты на изображении распознаёт модель. Их машинной проверки по исходному тексту нет: evidence_check.mode=visual_review_required. Работоспособность кнопок, скрытые разделы, мобильная версия и качество цветов по скриншоту не проверяются.

## Изменение относительно версии 0.3

Формат ответа изменён: общие списки strengths/weaknesses заменены отраслевыми условиями и выводами с цитатами. visual_style_score заменён на design_score и отдельные критерии. Потребителям старого JSON нужно перейти на schema_version=0.4.

Для подробного ответа стандартный предел увеличен до 6000 выходных токенов. Это потолок длины, а не обязательный расход на каждый запрос. Пользовательский предел можно задать в .env; автоматических платных повторов нет.

Формальные схемы: [text-analysis.schema.json](text-analysis.schema.json) и [image-analysis.schema.json](image-analysis.schema.json). Дополнительные проверки согласованности статусов и ссылок выполняются кодом после ответа модели.

При проверке цен похожее на описание значение в поле сорта (например, фраза про махровый цветок и аромат) получает отдельную отметку в price_checks. Это частная проверка типичной ошибки, а не полная проверка названий сортов.
